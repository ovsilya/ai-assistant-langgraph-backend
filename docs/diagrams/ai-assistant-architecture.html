AI Assistant: a reading assistant for magazine brand sites

A chat widget on a publisher's brand sites answers readers' questions and recommends articles from the brand's own archive. The backend is a Python / FastAPI service running a deterministic LangGraph workflow: load context, input guardrail and intent router, article retrieval (RAG), generation through the company AI gateway, then follow-ups and an output guardrail in parallel (one retry, then a safe fallback). Chats live in Valkey and DynamoDB. Every node is traced in LangSmith and measured in Datadog, and the traces feed the evaluation loop.
Endpoint: POST /v1/assistant/chat/{site_id} Models: Claude Sonnet (answer) · Haiku (guardrails, follow-ups, title) Multi-tenant: client → brand → site Runs on: AWS · Kubernetes Evaluation: 2 datasets · 14 evaluators · 3 experiments

4 · Data model and monitoring detail

DynamoDB models (Pydantic)

Message, one chat line: conversation_id (PK), message_id (SK, ULID), role, content, created_at, recommendations, topics, follow-ups, model_name, guardrail, ttl.

Conversation, one summary row per thread (the "past conversations" list): user_id (PK), conversation_id (SK), site_id, created_at, last_message_at, LLM-generated title, last-message preview, message_count, ttl.

Why models: they serialize items for DynamoDB, validate data before the write, fill in defaults, and give one definition of a message and a conversation. Writes happen in persist_conversation(), a background task after the graph finishes.

5 · Deployment pipeline

Merge code → GitHub Actions builds the image → push to ECR → the company deploy CLI tells Kubernetes to run it → new pods roll out → live.
1TriggerOpen a PR or create a release. .github/workflows/main.yml checks out the code and installs the deploy CLI.
2Build and testBuild a CI image (Dockerfile, BUILD_ENV=DEV) and run ruff (lint) and pytest inside it. Tests gate the release.
3PackageBuild the prod image and push it to AWS ECR as ai-assistant:<git-sha>.
4Deploy to KubernetesPR → feature environment; release → staging. Kubernetes reads k8s/deployment.yml, fills in the env variables, rolls out pods and health-checks them.

6 · Design choices

  • Workflow, not agent: fixed routing keeps latency, cost and behaviour predictable for a public widget, and makes each step testable on its own.
  • Cheap model for checks: Haiku guards, routes, and writes follow-ups and titles; Sonnet only writes the answer.
  • Parallel where safe: the two retrieval calls, and follow-ups alongside the output guardrail, joined in a named fan-in node.
  • Bounded retries: one retry with a corrective instruction, then a safe fallback; an unchecked answer is never sent.
  • Graph stays pure: it only returns state; persistence runs as a background task, so storage latency never delays the stream.
  • Config, not code, per brand: persona, filters and length come from the multi-tenant config service.
